# TinyInstaller Releases

Official release repository for **TinyInstaller**, an automated operating system deployment platform for supported VPS, cloud, and server environments.

TinyInstaller helps users deploy or redeploy supported Windows and Linux environments on servers they own or control, including situations where provider recovery tools, VNC consoles, or automated installers are unavailable or limited.

TinyInstaller is an independent deployment automation service. It is not a hosting provider, cloud provider, managed service provider, or operating system vendor.

## About This Repository

This repository contains public release artifacts used by the TinyInstaller service, including:

- Bootstrap scripts
- Prebuilt TinyInstaller binaries
- Supporting deployment files

These artifacts are downloaded automatically by the generated TinyInstaller installation command. They are intended for use with the TinyInstaller service and generally should not be downloaded, modified, or executed directly.

## How TinyInstaller Works

A typical deployment follows this workflow:

```text
Existing Supported Server
        │
        ▼
Run Generated Installation Command
        │
        ▼
Download TinyInstaller Components
        │
        ▼
Select Deployment Profile
        │
        ▼
Detect and Prepare Environment
        │
        ▼
Reboot into Installer
        │
        ▼
Deploy Operating System
        │
        ▼
Configure Network and Remote Access
        │
        ▼
Windows or Linux Ready
```

Depending on the selected deployment profile and environment, TinyInstaller can automate environment detection, disk preparation, network configuration, operating system deployment, boot configuration, and remote access setup.

Deployment progress can be monitored through the TinyInstaller web interface.

## Supported Deployments

TinyInstaller supports selected deployment profiles for:

- Windows Server
- Windows desktop environments
- Linux distributions
- VPS and cloud instances
- Custom operating system images
- Certain dedicated or bare-metal servers

Compatibility depends on the server provider, virtualization platform, CPU architecture, boot mode, hardware, and selected deployment profile. Compatibility with every provider, server, or configuration is not guaranteed.

Custom profiles can use RAW disk images or virtual disk formats supported by QEMU. Compressed RAW images such as `.raw.zst` are recommended for efficient deployment.

## Installation Command

TinyInstaller generates installation commands using your access key and selected deployment configuration.

A generated command typically downloads and runs a bootstrap script:

```bash
(wget <setup-url> -4O setup.sh || curl <setup-url> -Lo setup.sh) && bash setup.sh <setup-key>
```

Additional parameters may be available to pre-select an image, configure credentials, select ports, skip confirmation prompts, or control the installation mode.

For security and compatibility, always use the installation command generated by TinyInstaller. Do not share your access key or setup key, and do not construct installation commands manually unless instructed by the official documentation.

## Customer Responsibilities

Before starting a deployment, you are responsible for ensuring that:

- You own or control the target server and are authorized by its provider to modify or reinstall its operating system.
- You have the required administrator or root access.
- You have valid rights, permissions, and licenses for any operating system or software you deploy.
- Important data has been backed up.

TinyInstaller provides deployment automation only. It does not provide operating system licenses, product keys, activation rights, or software ownership.

## Warning

TinyInstaller performs low-level disk and operating system deployment operations.

**Running an installation may overwrite the target disk and permanently destroy existing data.**

Deployment may fail or temporarily make a server inaccessible, depending on the target environment and provider restrictions.

Always verify the target server, confirm that it is supported, and back up important data before starting a deployment.
